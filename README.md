## Qué vas a hacer

1. Elegir un proceso del negocio y una pregunta recurrente.
2. Identificar fuentes, vigencia, responsables y permisos.
3. Consultar el lote y contrastar cada respuesta con el original.
4. Registrar errores, ausencias y decisiones de mantenimiento.
5. Decidir si ampliar, corregir o detener la prueba.

## Pruébalo sin datos de tu empresa

El ejemplo trata la recepción de solicitudes. Incluye una regla vigente, su versión anterior y un reporte operativo. Puedes comprobar si una respuesta distingue registrar de confirmar y reconoce que no existe un plazo universal de entrega.

Para observar una primera respuesta sin darle la solución al asistente, no cargues junto con el lote la carpeta `REVISION/`. Compara después el resultado con los originales y la pauta de control.

## Qué permite y qué sigue sin probar

Es una estructura para un piloto pequeño. No instala un buscador, conecta servicios ni configura controles técnicos de acceso. No contiene documentos de clientes ni información real de empresas.

Se revisaron contenido, referencias y empaquetado. Una prueba con un receptor nuevo y una evaluación independiente de respuestas siguen pendientes. Las preguntas y respuestas de control no son resultados medidos de un modelo.

Antes de usar datos reales, confirma autorización, permisos efectivos y condiciones del entorno elegido. Conserva los originales sin alterarlos.
